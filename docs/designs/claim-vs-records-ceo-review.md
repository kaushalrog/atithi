## Step 0

### 0A. Premise challenge

- **The real problem:** a business owner gets hurt when the agent tells a customer something false about an action (booked, saved, the price).
- **The founder's proxy:** a builder wants to know about that before the business owner does.
- **Does the plan solve it directly?** Directly for VoxAgent, through its own traces and records. For outside builders it solves it only if they hold exportable traces and records, which is unverified and the plan's biggest assumption.
- **Cost of doing nothing:**
  - VoxAgent keeps no structured evidence for phone calls (M2). A wrong booking on the first pilot would be undiagnosable.
  - The portal's conversion number keeps lying (M1, measured: 100% for 0 bookings).
  - These cost a pilot sale. That's real, and it's independent of whether outside builders want the checker.
- **Key observation:** half of this plan pays off **even if the demand test fails**:
  - the structured trace
  - the M1/M2 fixes
  - the record-mismatch and double-booking checks run on VoxAgent's own calls

  The outside-builder half is the speculative bet. The plan should say so explicitly.

## Review sections

### Section 1: Architecture

```
                 RECEPTIONIST (existing)                      CHECKER (new, offline)
  channels: main.py, voice_main.py, server.py (/api/chat),    package (name TBD, eng review)
            telephony.py (phone), live_main.py (live)           trace     load + validate
                 |                                              mapping   tool name -> type/ok (yaml.safe_load)
                 v                                              records   CSV/JSON + snapshot, matching
  agent.ReceptionistAgent.history  (tool_calls + tool results)  checks    1, 2a, 3, 4, 6 as pure functions
     + NEW: per-entry `at` timestamps (aware, business tz)      outcome   task outcome
     + NEW: phone/live append tool calls (fixes M2)             report    text, JSON run, escaped HTML
                 |                                              compare   diff two run files
                 v  call end (not on the caller-to-answer path)    ^
  storage.save_call_log  ---- writes ---->  calls/<client>/<id>.json (unchanged shape)
                         ---- NEW ------->  trace (location: decision ARCH-1)  ----------+
                         reads bookings.db (snapshot rows for touched dates + caller's leads)
```

The dependency is one-way: the checker reads files and never imports `agent`, `storage` or `server`. That keeps it usable on outside traces and keeps provider code out (CLAUDE.md principle 6).

- **OK: rollback.** The trace is additive. Revert the commit and old call logs keep working. The checker reports calls without a trace as `skipped: no trace`, never as clean.
- **WARNING: timezone (P8).** There is no timezone in VoxAgent. A repair is needed to meet the approved trace contract (offset required):
  - default `Asia/Kolkata`, plus an optional `timezone:` key in the client YAML
  - stamp aware datetimes in the trace only
  - scheduling's naive local time stays unchanged in this release

  This is a repair of an approved requirement, not a new decision.
- **WARNING: phone call-end work.** The call-end snapshot and trace write run in `TwilioBridge.finish()` on the event loop, like today's `save_call_log`. That's the same class of risk as M8 (TODOS). The eng review decides whether `finish()` moves to `asyncio.to_thread`. It doesn't block this release, because live calls are off by default.
- **ARCH-1 (decision): where the trace lives.** `/api/dashboard` returns full call records (server.py:691-701). A `trace` key inside the call JSON would ship every action plus `records_snapshot` (other callers' names and phones) to the browser on every refresh. Also, `storage.read_call_logs` treats every `*.json` in `calls/<client>/` as a call (storage.py:612-615), so a sibling `<id>.trace.json` would be miscounted.

**ARCH-1 resolved (D7):** traces go to `calls/<client>/traces/<call_id>.json`, written by `storage.save_call_log` under its existing lock. The dashboard and call counting are unchanged. `calls/` is already gitignored, so traces never get committed.

### Section 2: Error & Rescue map

```
  CODEPATH                         | WHAT CAN GO WRONG                     | CLASS
  ---------------------------------|---------------------------------------|---------------------------
  storage.save_call_log (trace)    | snapshot query fails (db locked/gone) | sqlite3.Error
                                   | trace not serialisable                | TypeError / ValueError
                                   | disk full / permission                | OSError
                                   | test mode, real path                  | the guard's existing error
  agent history stamping           | none (in-memory append)               | —
  checker: load trace              | file missing / unreadable             | FileNotFoundError, OSError
                                   | not JSON / bad encoding               | json.JSONDecodeError, UnicodeDecodeError
                                   | schema invalid, > 1 MB, > 500 turns   | ValidationError (pydantic) / TraceError
                                   | naive timestamp (no offset)           | ValidationError
  checker: mapping YAML            | unknown tool name                     | (not an error) -> type=other, counted
                                   | malformed YAML                        | yaml.YAMLError
  checker: records                 | missing column / bad date             | RecordsError (row-level)
                                   | CSV encoding (Excel cp1252)           | handled like storage._read_legacy_csv
  checker: report/compare          | run files from different versions     | CompareError (refuse, say why)

  CLASS                 | RESCUED? | RESCUE ACTION                                         | USER SEES
  ----------------------|----------|-------------------------------------------------------|-------------------------------
  trace-write errors    | Y        | log call_id + class; call JSON still written          | caller: nothing; owner: call shown; checker: "skipped: no trace"
  test-mode guard error | N (by design) | raises in tests, as the existing guard does      | test failure (intended)
  FileNotFound/OSError  | Y        | per-file error line; exit code 2 if any input failed  | "cannot read <path>: <reason>"
  JSONDecode/Unicode    | Y        | per-file rejection with line/column                  | "not valid JSON at line 3"
  ValidationError       | Y        | per-file rejection naming the field                   | "turns[4].at: missing UTC offset"
  unknown tool          | Y        | type=other, listed in summary                        | "2 actions had unmapped tools: X"
  yaml.YAMLError        | Y        | abort before any check                               | "mapping file invalid: ..."
  RecordsError          | Y        | row skipped, listed; never silently dropped          | "records row 12 skipped: bad date"
  CompareError          | Y        | refuse to diff                                        | "runs used checker v1 and v2"
```

- **GAP (repaired within scope):** a call with no trace, a rejected trace or a skipped records row must appear in the run summary as `skipped` with a reason, and never count as clean. This is required by "zero silent failures" and by the approved "malformed input is rejected with a clear error". **Exit codes:** 0 = ran, no findings; 1 = findings; 2 = some input rejected. CI can then fail on 1 or 2.
- **Catch-all:** the trace write uses `except Exception` around the trace build only. This one catch-all is justified, because a trace bug must never kill the call record, and it is logged with call_id and class. Name it in a comment.

### Section 3: Security & threat model

| Threat | Likelihood | Impact | Mitigated? |
|---|---|---|---|
| Script in transcript text runs in the HTML report | Med (outside logs) | High | Yes: `html.escape` on all trace text, no external assets, CSP meta, adversarial fixture (approved) |
| Prompt injection in transcripts | Med | Low (no LLM in checker) | Yes: deterministic checks, no model call |
| YAML mapping executes code | Low | High | Yes: `yaml.safe_load`; `ok_when` is field equality, never `eval` (approved) |
| Huge or deeply nested JSON exhausts memory | Low | Med | Yes: size checked **before** parse (≤ 1 MB), ≤ 500 turns |
| Run files and reports leak PII via git | Med | High | **Repair:** add `runs/` and `reports/` (default output dirs) to `.gitignore`; phones masked to last 4 (approved) |
| Trace snapshot shown cross-tenant | Low | High | Yes: traces live per client folder; checker is a local CLI with no server endpoint (D7) |
| New server endpoint | — | — | None added in this release |
| New dependencies | — | — | None, or pydantic pinned (pending, eng review/Sai; CLAUDE.md requires justification) |

### Section 4: Data flow & edge cases

```
  trace file -> size check -> json.loads -> schema validate -> map tool types -> run checks -> findings
     |shadow       >1MB:reject   bad JSON:reject  naive time/bad enum:reject  unknown:other  empty turns: no_intent
  records file -> parse rows -> normalise phone/date/time -> index by (phone10,date,HH:MM) and booking_id
     |shadow       bad row: skip+list   phone <10 digits: keep, never matches -> "record missing" is avoided by listing it as unverifiable
  run JSON -> compare(a,b) keyed on (check, call_id, evidence key) -> new / fixed / unchanged
     |shadow       version mismatch: refuse   call only in one run: "only in A/B", not "fixed"
```

| Edge case | Handled? | How |
|---|---|---|
| Trace with 0 turns or 0 actions | Yes | outcome `no_intent`, no findings |
| Same call_id twice in one run | Repair | reject the second, list it |
| Compare runs over different call sets | Repair | "only in A / only in B", never counted as fixed |
| Booking cancelled after call | Yes | `unverifiable: changed after call` (approved) |
| Two calls book the same slot within ms | Yes | the bookings.db unique index prevents it; check 3 is a regression guard on VoxAgent and proven on fixtures |
| Checker run at different wall-clock times | Repair | the checker never calls `now()`. All time comes from the trace, so results are reproducible (approved: "results are reproducible") |

There's no async ordering concern in the checker (it's single-process and synchronous). For the trace write, ordering is the existing `save_call_log` lock.

- **2am-Friday test:** the M2 phone regression. A fake phone call books, and the trace shows the action, the record matches and the outcome is `booked`.
- **Hostile QA test:** the adversarial transcript, plus a trace claiming `ok=true` with no record.

### Section 7: Performance

- **Hot path:** a timestamp per history append (nanoseconds). bench.py gains the append measurement (approved).
- **Call end:** one indexed SQLite read (`bookings_by_client`) plus one extra file write. It's off the caller-to-answer path. On phone it sits on the event loop (Section 1 WARNING).
- **Checker:** O(turns + actions + records) per trace, bounded by the 1 MB cap. Records are indexed once per run.

### Section 8: Observability

- **CLI summary line:** traces read, rejected (reason), skipped, findings per check, heuristic share, unverifiable, ambiguous, and per-outcome counts.
- **Receptionist side:** the trace-write failure is logged with call_id and exception class. Portal M1 is not in this release (METRICS §3).
- **Debuggability:** every finding carries the turn index and text, the action, and the record row or its absence. A bug report from 3 weeks ago can be reproduced by re-running the same trace (replay).
